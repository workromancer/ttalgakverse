# 고정된 것과 새로 짓는 것

딸각verse 는 **기술 스택만 고정**하고, 모양은 사용자가 말하는 대로 **그 프로젝트 전용 코드를 새로 짓는다.**
템플릿의 토끼 캐릭터·광화문·한옥·세빛섬 같은 것은 고르는 **메뉴가 아니라 예시**다 — "이 정도 수준으로 이렇게 지으면 된다"는 참고.

## 고정 (바꾸지 않음)

| | |
|---|---|
| 엔진 | three.js + Vite, `src/main.js` (이동·카메라·포털·구역 전환·멀티플레이 연결·HUD) |
| 데이터 | `world/world.json` (구역·소품 배치·포털), `world/concept.json` (색·빛·캐릭터) |
| 멀티플레이 | Supabase Realtime (`src/net.js`) |
| 배포 | Cloudflare Workers 정적 자산 |
| 보안 | 비밀 정보 검사 훅 |

## 새로 짓는 곳 (파일만 넣으면 엔진이 자동으로 불러옴)

| 폴더 | 무엇 | 형식 | 연결 |
|---|---|---|---|
| `src/avatars/<id>.js` | 캐릭터 스타일 | `export default { label, icon, build(ch, M, kit) }` | `concept.json` → `avatar.style`, 방문자가 고르게 하려면 `avatar.styles: [...]` |
| `src/props/<kind>.js` | 건물·랜드마크·소품 | `export default (p, kit) => ({ group, solid })` | `world.json` → `props[].kind` |
| `src/scenes/<name>.js` | 구역 연출 (지형·날씨·빛·움직이는 것) | `export default (ctx) => ({ update?(dt, t), dispose?() })` | `world.json` → 구역 `scene` (또는 최상위 `scene` = 모든 구역) |

- 각 폴더의 `_example.js` 가 복사해서 시작할 견본이다 (`_` 로 시작하는 파일은 엔진이 무시).
- **import 를 쓰지 않는다** — 필요한 건 전부 `kit`/`ctx` 로 들어온다. 그래서 같은 파일이 월드·🛠️ 작업대(`lab.html`)·라이브 보드(`/avatars/`)에서 그대로 돈다.
- 같은 이름이면 프로젝트 것이 기본 것을 이긴다 (예: `src/props/tree.js` 를 만들면 모든 나무가 바뀜).
- 검사: `validate.mjs` 는 `src/props/`·`src/scenes/` 에 있는 이름을 알아서 인정한다.
- 이 셋으로도 안 되는 것 (새 조작 방식, 미니게임, 실내 다층 구조 등)은 `src/main.js` 를 직접 고친다. 고친 내용은 PROGRESS.md 에 남긴다.

## 짓는 순서 (캐릭터·구조물·연출 공통)

1. **말을 그대로 받는다** — 목록에서 고르게 하지 않는다. "남극 펭귄인데 목도리 두른", "우리 카페 건물", "벚꽃 잎이 흩날리는 언덕" 처럼 자유롭게. 사진·브랜드 마스코트·좋아하는 게임 캐릭터 느낌도 받는다 (특정 작품의 캐릭터를 그대로 베끼지는 않고, 느낌만 가져온 오리지널로).
2. **누가 봐도 알아볼 특징 3~5개**로 바꿔 보여 준다 ("펭귄 = 검은 등·흰 배·주황 부리와 발·짧은 날개·뒤뚱 걸음").
3. **해석 2~3개를 새로 지어** 나란히 보여 준다 (비율·디테일·귀여움 정도를 다르게). 캐릭터는 `/avatars/` 보드, 구조물은 작업대, 연출은 월드 화면.
4. 고르거나 섞고, 고칠 점을 받아 반복 → 확정. 확정 안 된 후보 파일은 `_` 를 붙여 보관하거나 지운다.

## 크기 기준 (1 단위 = 1m)

캐릭터 키 0.9~1.2 (이름표 1.4) · 문 높이 2.2~3 · 한 층 3~4 · 가로등 3~4 · 나무 3~6 · 구역 20~50.
