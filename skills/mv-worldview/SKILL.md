# 2단계 · 세계관 인터뷰 (mv-worldview)

목표: 고정된 예시를 고르게 하는 게 아니라, **사용자 답을 듣는 즉시 그 사람만의 세계관 초안을 그려서** 라이브 화면으로 보여 주고 함께 다듬는다. 결과는 `world/world.json`.

언어: 사용자가 쓰는 언어(한국어/영어)로 묻고 답한다. 화면 문구도 그 언어로.

## 0) 라이브 보드 열기 (인터뷰 시작 전에)

```bash
mkdir -p worlds
cp <이 스킬 폴더>/assets/worlds.html worlds/index.html
echo '[]' > worlds/drafts.json
node <키트 루트>/shared/live-preview.mjs . 4321   # 백그라운드로 실행, 이미 떠 있으면 그대로 씀
```
→ 사용자에게 **http://localhost:4321/worlds/** 를 열어 두라고 한다 (휴대폰은 나온 Network 주소). 이후 `worlds/interview.json`·`worlds/drafts.json` 을 고치면 화면이 저절로 바뀐다.
(키트 루트 = 이 SKILL.md 폴더의 `../..`)

## 1) 인터뷰 — 한 번에 하나씩, 답할 때마다 화면 갱신

질문 목록을 `worlds/interview.json` 에 `[{ "q": "...", "a": "" }]` 로 먼저 써 두고(화면에 "아직 안 물어봄"으로 보임), 답을 받을 때마다 `a` 를 채운다.

| # | 질문 (예) | 왜 묻나 |
|---|---|---|
| 1 | 사람들이 어떤 **장소**에서 만나면 좋겠어요? 떠오르는 장면을 한 문장으로 | 세계의 뼈대 |
| 2 | **누가** 오나요? (친구들, 팬, 동아리, 손님…) | 규모·구역 성격 |
| 3 | 와서 **무엇을** 하나요? (수다, 구경, 공연, 홍보, 게임…) 2~3개 | 구역마다 할 일 |
| 4 | 꼭 있었으면 하는 **장소나 물건** 하나 | 상징 구역·소품 |
| 5 | 처음 들어오면 **어디부터** 보여 주고 싶어요? | spawn |

- 답이 짧거나 막막해하면 보기 3개를 즉석에서 만들어 준다 (고정 목록 아님, 앞 답에 맞춰서).
- **실제 장소**(한강공원, 경복궁, 석촌호수, 우리 동네 공원…)를 원하면 임팩트가 크다. 이름난 건축물은 사진을 찾아보고 실루엣·색·재질·배치를 맞춘다. 엔진에 없는 건물은 4단계에서 `src/props.js` 에 새 kind 로 만든다 (사진 → 특징 3~5개 → 기본 도형 조합).
- **2번 답을 받은 순간부터** 초안을 그린다: 1·2번만으로 서로 다른 해석 2~3개를 `drafts.json` 에 쓰고 "화면 보세요" 라고 말한다. 이후 답마다 초안을 고쳐 쓴다 (사용자는 세계가 자라는 걸 보게 됨).
- 초안끼리는 확실히 다르게: 규모(작은 골목 vs 큰 광장), 실내/야외, 동선(한 줄 vs 허브형).

## 2) 초안 형식 (`worlds/drafts.json`)

```json
[{ "id": 1, "pitch": "한 줄 소개", "audience": "누가 오는지", "activities": ["할 일", "..."],
   "world": { /* world.json 과 같은 형식 — 키트 docs/world-schema.md */ } }]
```
world 작성 규칙:
- 구역 3~5개, 형태 `open`(야외)/`room`(실내), 크기 20~50m, 가운데가 (0,0), 시작 지점 (0,4) 근처는 비우기.
- 소품은 엔진이 그릴 수 있는 것 — 목록과 필드는 키트 `docs/world-schema.md` (기본·골목·자연·서울 랜드마크 30여 종). 없는 건 비슷한 것으로 근사하고 "4단계에서 진짜 소품으로 만들 수 있어요" 라고 말해 둔다.
- 바닥 무늬(`pattern`·`areas`)·물(`water`)·배경(멀리 보이는 `mountain` `tower` `bridge`)을 써서 장면에 깊이를 준다. 빈 바닥 + 소품 몇 개는 허접해 보인다.
- 포털은 양방향. 야외는 가장자리 2~3m 안, 실내는 벽 위 좌표(벽에 문이 뚫림).
- `slug` 영문 소문자·숫자·`-`.

## 3) 고르고 다듬기 → 확정

- "1번으로", "2번에 호수 추가" 같은 답 → drafts 를 고쳐 다시 보여 준다 (보통 1~3번 오감).
- 확정하면 그 `world` 를 `world/world.json` 으로 저장하고 검사:
  `node <이 스킬 폴더>/reference/validate.mjs world/world.json` → 문제는 고친다.
- 인터뷰 답은 `world/interview.json` 으로도 복사해 둔다 (다음 단계·나중 세션이 참고).

## 끝나면

- `state.project.name/slug`, `state.choices.worldview`(초안 번호·한 줄), `steps.worldview.status = "done"`.
- PROGRESS.md 에 인터뷰 답 요약 + 구역 표.
- 라이브 서버는 그대로 둔다 (다음 단계 컨셉 보드도 같은 서버에서 /concepts/ 로 열림).
