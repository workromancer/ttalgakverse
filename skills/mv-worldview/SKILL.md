# 2단계 · 세계관 인터뷰 (mv-worldview)

목표: 고정된 예시를 고르게 하는 게 아니라, **사용자 답을 듣는 즉시 그 사람만의 세계관 초안을 그려서** 라이브 화면으로 보여 주고 함께 다듬는다. 결과는 `world/world.json`.

언어: 사용자가 쓰는 언어(한국어/영어)로 묻고 답한다. 화면 문구도 그 언어로.

## 0) 라이브 보드 열기 (인터뷰 시작 전에)

```bash
mkdir -p worlds
cp <이 스킬 폴더>/assets/worlds.html worlds/index.html
echo '[]' > worlds/drafts.json
node <키트 루트>/shared/live-preview.mjs . 4321   # 백그라운드로 실행, 이미 떠 있으면 그대로 씀. 4321 을 다른 앱이 쓰면 다음 빈 포트로 열림 → 출력에 나온 주소로 안내
```
→ 사용자에게 **http://localhost:4321/worlds/** 를 열어 두라고 한다 (휴대폰은 나온 Network 주소).
**보드에서 답하고 고르기**: 지금 질문은 보드에 예시 버튼과 입력칸으로 뜬다. 사용자는 예시를 눌러(섞어도 됨) 보드에서 답하거나 채팅으로 답한다. 인터뷰 시작부터 `node <키트 루트>/shared/wait-choice.mjs worlds` 를 **백그라운드로** 띄워 두고, 끝나면 출력의 `type` 을 본다 — `answer` 면 (interview.json 에 이미 저장됨) 초안을 고치고 다음 질문의 `ex` 를 그 답에 맞게 쓴 뒤 다시 띄운다, `choice` 면 아래 3)으로. 이후 `worlds/interview.json`·`worlds/drafts.json` 을 고치면 화면이 저절로 바뀐다.
(키트 루트 = 이 SKILL.md 폴더의 `../..`)

## 1) 인터뷰 — 한 번에 하나씩, 답할 때마다 화면 갱신

질문 목록을 `worlds/interview.json` 에 `[{ "q": "...", "ex": ["예시", ...], "a": "" }]` 로 먼저 써 두고(화면에 "아직 안 물어봄"과 예시가 보임), 답을 받을 때마다 `a` 를 채우고 다음 질문의 `ex` 를 그 답에 맞게 고쳐 쓴다.

질문마다 **예시 3~4개를 같이** 준다 (길잡이 스킬의 「질문할 때는 항상 예시와 함께」). 아래 예시는 첫 질문용 출발점 — 2번부터는 앞 답에 맞춰 새로 만든다.

| # | 질문 | 예시 (출발점 — 앞 답에 맞춰 바꿈) | 왜 묻나 |
|---|---|---|---|
| 1 | 사람들이 어떤 **장소**에서 만나면 좋겠어요? | 벚꽃 핀 한강 공원 피크닉 · 비 오는 밤 골목 LP바 · 구름 위에 떠 있는 도서관 · 우리 학교 옥상 | 세계의 뼈대 |
| 2 | **누가** 오나요? | 단톡방 친구 10명 · 내 유튜브 구독자 · 동아리 신입생 · 우리 가게 손님 | 규모·구역 성격 |
| 3 | 와서 **무엇을** 하나요? 2~3개 | 둘러앉아 수다 · 작품·사진 전시 구경 · 작은 공연 · 숨은 물건 찾기 | 구역마다 할 일 |
| 4 | 꼭 있었으면 하는 **장소나 물건** 하나 | 소원 거는 큰 나무 · 단골 카페 창가 자리 · 모두 이름 남기는 방명록 벽 · 밤마다 뜨는 큰 달 | 상징 구역·소품 |
| 5 | 처음 들어오면 **어디부터** 보여 주고 싶어요? | 정문에서 전체가 내려다보이게 · 4번에서 말한 그곳 바로 앞 · 아늑한 작은 방에서 시작해 문 열고 나가기 | spawn |

- 예: 1번에 "LP바"라고 했다면 3번 예시는 "신청곡 틀기 · 레코드 구경 · 바 자리에서 수다 · 작은 디제잉 무대"처럼 그 세계 안의 장면으로.
- "모르겠어요" → 앞 답에 가장 어울리는 걸 골라 초안에 넣고 넘어간다 (보드에서 바꿀 수 있다고 한 줄).
- **목록에 맞추지 말고 말한 그대로 받는다.** 엔진의 기본 소품(서울 랜드마크 등)은 예시일 뿐 — "우리 학교 운동장", "구름 위 떠 있는 도서관", "레트로 오락실 골목" 이면 그 세계를 그대로 설계한다. 기본 소품에 없는 건물·물건·연출은 새 `kind`/`scene` 이름을 지어 초안에 넣고, 4단계에서 프로젝트 전용 코드(`src/props/<kind>.js`, `src/scenes/<name>.js`)로 짓는다 (키트 `docs/custom-code.md`).
- **실제 장소**(한강공원, 경복궁, 우리 동네 공원…)는 사진을 찾아보고 실루엣·색·재질·배치를 맞춘다 (사진 → 특징 3~5개).
- **2번 답을 받은 순간부터** 초안을 그린다: 1·2번만으로 서로 다른 해석 2~3개를 `drafts.json` 에 쓰고 "화면 보세요" 라고 말한다. 이후 답마다 초안을 고쳐 쓴다 (사용자는 세계가 자라는 걸 보게 됨).
- 초안끼리는 확실히 다르게: 규모(작은 골목 vs 큰 광장), 실내/야외, 동선(한 줄 vs 허브형).

## 2) 초안 형식 (`worlds/drafts.json`)

```json
[{ "id": 1, "pitch": "한 줄 소개", "audience": "누가 오는지", "activities": ["할 일", "..."],
   "world": { /* world.json 과 같은 형식 — 키트 docs/world-schema.md */ } }]
```
world 작성 규칙:
- 구역 3~5개, 형태 `open`(야외)/`room`(실내), 크기 20~50m, 가운데가 (0,0), 시작 지점 (0,4) 근처는 비우기.
- 소품 `kind`: 기본 소품(키트 `docs/world-schema.md`)이 맞으면 쓰고, 없으면 **비슷한 걸로 때우지 말고** 새 이름을 짓는다 (`"kind": "cloud-library"`, 필드도 자유롭게: `floors`, `color` …). 이런 새 kind·scene 은 초안의 `"build": [{ "kind": "cloud-library", "desc": "구름 위 3층 원형 도서관, 책장이 밖으로 보이는 유리벽" }]` 에 적어 둔다 → 4단계가 이 목록대로 짓는다.
- 평평한 바닥으로 안 되는 것(언덕·계단식 지형·눈·비·떠다니는 섬·오로라·하늘 연출)은 구역 `"scene": "<이름>"` 으로 적고 같은 `build` 목록에 넣는다.
- 바닥 무늬(`pattern`·`areas`)·물(`water`)·배경(멀리 보이는 `mountain` `tower` `bridge`)을 써서 장면에 깊이를 준다. 빈 바닥 + 소품 몇 개는 허접해 보인다.
- 포털은 양방향. 야외는 가장자리 2~3m 안, 실내는 벽 위 좌표(벽에 문이 뚫림).
- `slug` 영문 소문자·숫자·`-`.

## 3) 고르고 다듬기 → 확정

- **브라우저에서 고르기** (HTML 보드에서 고르는 방식은 그대로 유지 — 채팅과 둘 다 됨): `wait-choice.mjs worlds` 가 백그라운드로 돌고 있게 한다 (Bash `run_in_background`). 사용자가 보드에서 「이 초안으로 할게요」를 누르면 이 명령이 끝나며 알림이 오고, 출력에 고른 id 와 고칠 점(note)이 있다 → 채팅을 기다리지 말고 바로 이어서 진행한다.
  - note 가 있으면 반영해 초안을 고쳐 다시 보여 주고 `rm -f worlds/choice.json` 후 wait-choice 를 다시 띄운다. note 가 없으면 확정.
  - 사용자가 채팅으로 먼저 고르면 그걸 따르고, 돌고 있는 wait-choice 는 그냥 두거나 멈춘다 (30분 뒤 저절로 끝남).
- 채팅으로 "1번으로", "2번에 호수 추가" 같은 답 → drafts 를 고쳐 다시 보여 준다 (보통 1~3번 오감).
- 확정하면 그 `world` 를 `world/world.json` 으로 저장하고 검사:
  `node <이 스킬 폴더>/reference/validate.mjs world/world.json` → 문제는 고친다.
- 인터뷰 답은 `world/interview.json` 으로도 복사해 둔다 (다음 단계·나중 세션이 참고). 고른 초안의 `build` 목록은 `world/build.json` 으로 (4단계의 할 일).
